# Эмма — голосовой прототип (агент)

Python-воркер на LiveKit Agents: Deepgram (STT) → языковая модель через LiveKit
Inference (LLM) →
Cartesia (TTS), с моделью turn-detection вместо голой VAD-паузы (см. находки
исследования про turn-taking как отдельную инженерную задачу).

Изменения по пути:
- Изначально планировался ElevenLabs, но он блокирует доступ из России (см.
  help.elevenlabs.io — санкционный список стран). Cartesia — рабочая замена.
- Языковая модель ходит через LiveKit Inference (`inference.LLM(model="openai/gpt-5.5")`):
  модели OpenAI и Google оплачиваются в LiveKit Cloud теми же ключами, что и
  комнаты, отдельный провайдер и ключ не нужны. До этого был OpenRouter — один
  ключ на Claude, GPT и Gemini, но с лимитом кредитов и лишней кассой. Claude
  через LiveKit Inference недоступен, поэтому в списке моделей его нет.
- Известный баг livekit-agents (github.com/livekit/agents/issues/4135, закрыт
  мейнтейнерами как "not planned"): первая отправка текста в TTS-стрим иногда
  проигрывает гонку с установкой websocket-соединения и падает с "no audio frames
  were pushed for text". Обходим явным прогревом соединения в начале `entrypoint`
  (см. `main.py`) — до старта сессии дожидаемся реального коннекта из пула Cartesia.

## 1. Заведи аккаунты и ключи

Скопируй `.env.example` в `.env` и впиши ключи:

```
cd agent
cp .env.example .env
```

- LiveKit: cloud.livekit.io → New Project → Settings → Keys (`LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`)
- Deepgram: console.deepgram.com → API Keys
- Cartesia: play.cartesia.ai → API Keys
- Modulate (Velma): platform.modulate.ai → API Keys (`MODULATE_API_KEY`). Без ключа
  воркер работает как раньше, но Velma выключена — см. раздел про настроение ниже.

## 2. Установи зависимости

```
cd agent
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Первый запуск скачает модели VAD/turn-detector — команда ниже сделает это заранее:

```
python main.py download-files
```

## 3. Запусти воркер (агент)

```
python main.py dev
```

Воркер подключится к LiveKit Cloud проекту и будет ждать участников в комнате.
Оставь это окно терминала открытым.

## 4. Запусти token-сервер (он же отдаёт страницу)

В отдельном терминале, тоже из `agent/` с активным venv:

```
uvicorn server:app --reload --port 8080
```

Один процесс и отдаёт страницу прототипа (`web/`), и обслуживает её API:
список моделей, характеров и голосов (`/catalog`) и одноразовую комнату +
токен (`/token`). Страница и API на одном домене, поэтому адрес сервера нигде
прописывать не нужно и CORS не настраивается.

Прототип закрыт входом: без него любая страница ведёт на `/login` (своя
страница в стиле прототипа, `web/login.html`), а `/catalog` и `/token` отвечают
401. В `.env` нужны `EMMA_AUTH_USER` и `EMMA_AUTH_PASSWORD` — общие логин и
пароль для команды. После входа сервер ставит подписанную cookie на 30 дней;
смена пароля сразу разлогинивает всех. Без входа открыты только `/login`,
`/health` и оформление страницы входа (css, шрифты, иконка).

## 5. Поговори с Эммой

Два варианта:

**Своя страница** — открой http://localhost:8080, выбери модель, характер и
голос, нажми «Talk to Emma». Файлы страницы лежат в `web/`. Прототип целиком
на английском: интерфейс, голоса Cartesia и промты агента.

Что происходит во время разговора: транскрипт речи приходит на страницу
штатным потоком LiveKit (`lk.transcription`); сигналы настроения от Velma —
в `emma.emotion` (см. раздел про настроение ниже).
Если падает звено конвейера (распознавание, модель, голос), воркер шлёт причину
в `emma.status`, и страница показывает её под кнопкой вместе с состоянием
микрофона, соединения и самой Эммы.
Кнопка «Закончить разговор» отправляет `end` в `emma.control`; воркер пишет
итог разговора в `emma.summary`, сохраняет транскрипт и только потом страница
отключается.

**LiveKit Agents Playground** (без своего фронтенда, для быстрой проверки) —
открой https://agents-playground.livekit.io, залогинься тем же LiveKit Cloud
проектом, подключись к любой комнате — воркер зайдёт в неё автоматически.

Если слышишь ответы Эммы и она реагирует на речь — пайплайн STT→LLM→TTS работает.

## 6. Деплой на Railway (чтобы ссылка работала без терминала)

Оба сервиса собираются из одного `agent/Dockerfile`, различаются только
командой старта. Сервис `token` одновременно отдаёт страницу прототипа, так что
GitHub Pages не нужен: прототип открывается прямо по адресу сервиса `token`.

1. railway.app → New Project → Deploy from GitHub repo → `emma-playground`.
2. В созданном сервисе: Settings → Source → Root Directory = `agent`.
   Переименуй сервис в `worker`. Команду старта не трогай (из Dockerfile:
   `python main.py start`).
3. Variables → вставь все ключи из `.env` (без `EMMA_AUTH_USER` и
   `EMMA_AUTH_PASSWORD` — воркеру они не нужны). Удобно через Raw Editor одним куском. Опционально:
   `EMMA_TRANSCRIPTS_DIR` — куда писать
   транскрипты (по умолчанию `transcripts/` рядом с кодом; без Railway Volume
   папка не переживает передеплой, но транскрипт дублируется в логи).
4. Второй сервис: в проекте нажми New → GitHub Repo → тот же репозиторий.
   Settings → Root Directory = `agent`, Custom Start Command =
   `uvicorn server:app --host 0.0.0.0 --port 8080`. Назови `token`.
   Порт пишем числом: у сборки из Dockerfile Railway не подставляет `$PORT`
   в команду старта, и uvicorn падает с `'$PORT' is not a valid integer`.
5. Variables для `token`: `LIVEKIT_URL`, `LIVEKIT_API_KEY`,
   `LIVEKIT_API_SECRET`, `EMMA_AUTH_USER` и `EMMA_AUTH_PASSWORD` (придумай
   логин и пароль для команды). Без них сервис не стартует.
6. Settings → Networking → Generate Domain у сервиса `token`, порт `8080`.
   Это и есть адрес прототипа (сейчас https://token-production-a25e.up.railway.app).

Проверка: `https://<домен token>/health` отвечает `{"ok": true}`; в логах
`worker` есть строка `registered worker`. После этого `https://<домен token>/`
показывает страницу входа, после неё открывает прототип и соединяет с Эммой.

Каждый пуш в `main` пересобирает оба сервиса.

## Velma: настроение собеседника

Velma — модель Modulate, которая слышит в голосе эмоции. Воркер стримит звук
собеседника в её полный streaming-анализ (`velma.py`) параллельно с Deepgram:
копия кадров из `Emma.stt_node` уходит в websocket Velma сырым PCM 16 кГц, а
первым кадром туда уезжает конфиг с шестью кастомными бихейверами. Сигнал
Эммы — одно из девяти семейств эмоций с палитры Modulate, из двух источников:

- **голос** — акустическая метка Velma на реплику (`partial_clip`, пока человек
  ещё говорит, затем `clip` и `clip_update`). Velma различает 26 меток, они
  складываются в семейства (таблица `FAMILIES` в `velma.py`):

  | семейство | цвет | метки Velma |
  |---|---|---|
  | angry | `rgb(238, 64, 86)` | Angry, Frustrated, Contemptuous |
  | disgusted | `rgb(219, 68, 124)` | Disgusted |
  | afraid | `rgb(209, 91, 162)` | Afraid, Anxious, Stressed, Concerned |
  | surprised | `rgb(228, 99, 130)` | Surprised |
  | happy | `rgb(248, 106, 86)` | Happy, Amused, Excited, Proud, Affectionate, Hopeful, Relieved, Confident |
  | sad | `rgb(0, 120, 200)` | Sad, Disappointed, Ashamed |
  | neutral | `rgb(97, 97, 118)` | Neutral, Calm |
  | other | `rgb(97, 97, 118)` | Interested, Bored, Tired, Confused |
  | unknown | `rgb(97, 97, 118)` | любая метка, которой нет в таблице |

- **слова** — детекции бихейверов «Says They Are Angry / Disgusted / Afraid /
  Surprised / Happy / Sad»: Velma судит по транскрипту и отдаёт уверенность и
  объяснение. Для серых семейств бихейверов нет.

Что происходит при сигнале (`main.py`, класс `Mood`):

- страница получает его в топике `emma.emotion` и на 5 секунд красит шар,
  свечение и ярлык над шаром в цвет семейства; серые семейства ничего не
  перекрашивают, только показывают ярлык (`Calm · voice`). На реплике навсегда
  остаётся плашка: для голоса с исходной меткой Velma (`Frustrated · voice`,
  красная), для слов с семейством и уверенностью (`sad · words · 0.97`); при
  наведении видно семейство, расшифровку Velma, уверенность и задержку от
  конца реплики. Серые плашки бледные;
- голос и слова не спорят: на одной реплике могут стоять обе плашки, даже если
  они называют разное (`Calm · voice` и `sad · words`). Плашка слов встаёт на
  тот клип, который Velma назвала доказательством (`definitive_clip_uuid`), а
  готовый клип без акустической метки получает `Unknown · voice`. Метка, уточнившаяся
  внутри семейства (partial Happy → final Amused), обновляет плашку без нового
  сигнала; смена семейства — новый сигнал;
- перед следующим ответом Эммы модель получает одноразовую системную заметку,
  в которую склеены голос и слова («the person's voice sounds calm right now.
  The person has just said they are sad»). Базовая инструкция в `catalog.py`:
  при злости, грусти, страхе и отвращении коротко спросить, что за этим стоит;
  при радости и удивлении подхватить тон без вопроса; если голос и слова
  расходятся, можно мягко это заметить. Одно семейство в течение минуты — один
  эпизод и одна реакция; серые семейства заметки не оставляют;
- всё сохраняется в транскрипт: `moods`, `velma.clips` (все метки с
  семейством) и `velma.behaviors`.

Строка «Velma» под кнопкой показывает, слушает ли она. Её сбой разговор не
роняет: причина уходит в лог событий. Проверить интерфейс и реакцию Эммы без
ключа и без крика в микрофон можно кнопками «Test a signal» (по одной на
цветное семейство), они появляются при `?dev` в адресе страницы и идут тем же
путём, что сигнал от Velma.

## Что показывает страница

Центр страницы — шар, это сама Эмма. Он дышит, пока она слушает; от него идут
кольца, пока она слышит собеседника, а под ним бежит расшифровка речи на лету;
он пульсирует с точками и счётчиком секунд, пока она думает; движется
столбиками, пока говорит; становится пустым с красной обводкой, когда что-то
сломалось, и под ним написано, что именно и что с этим делать. Подпись под
шаром: Listening, Hearing you, Thinking…, Speaking, Stopped. Ниже — кнопка и
подробная цепочка «микрофон → соединение → Эмма → Velma».

Слева под настройками — лог событий с секундами от начала разговора: состояния
Эммы, сигналы, метки Velma, время ответа по звеньям, сбои. Справа — реплики с
плашками сигналов.
